# Esquema de Base de Datos - DataMap

Documento generado el 2025-11-08 con análisis del proyecto Relan

## 1. TABLAS PRINCIPALES

### users
UUID PK, soporta soft delete, control de login attempts, IP tracking

### projects  
UUID PK, owner_id FK, soft delete, especifica BD origen/destino

### project_members
UUID PK, membresía con roles (editor/viewer), unique(project_id, user_id)

### tables (Meta-tabla)
SERIAL PK, project_id FK, name + type ('origin'/'destination')
- Soporta cifrado: name_encrypted + name_nonce + is_encrypted flag
- Constraint CHECK para garantizar plaintext O encrypted

### columns
SERIAL PK, table_id FK
- Propiedades: name, data_type, is_nullable, is_primary, is_autogenerated
- Soporta cifrado de nombre y data_type
- Constraints CHECK para integridad de cifrado

### mappings
SERIAL PK, project_id FK
- origin_table, origin_column -> destination_table, destination_column
- transformation_logic (opcional)
- Todas las columnas pueden estar cifradas
- Constraints CHECK para validar cifrado

### primary_key_constraints
UUID PK, table_id FK UNIQUE
- Migración 001: Soporta PKs compuestas
- column_ids: UUID array

### project_encryption  
UUID PK (project_id), Migración 003
- master_key_hash: Argon2id one-way
- salt_verification: 128 bits base64
- salt_key_derivation: 128 bits base64
- encryption_enabled: flag

### subscription_plans
VARCHAR PK (id), planes: free/pro/etc
- max_projects, max_tables, max_columns_per_table
- Integración Stripe
- features: JSONB

### subscriptions
UUID PK, user_id+project_id FK
- Integración Stripe (subscription_id UNIQUE)
- status: trialing/active/past_due/canceled/incomplete/incomplete_expired/unpaid/paused
- INDEX UNIQUE: uniq_active_sub_per_user_project (max 1 activa por user+project)

### security_logs
BIGSERIAL PK, auditoría
- event_type, ip_address, user_id, endpoint
- details: JSONB
- severity: info/warning/error/critical

### security_rate_limits
SERIAL PK, rate limiting
- unique(ip_address, endpoint)
- attempt_count, blocked_until

## 2. ALGORITMO DE CIFRADO (Migración 003)

**Algoritmo**: AES-256-GCM
**Derivación**: Argon2id
**Nonce**: 96 bits (base64)

Flujo:
1. Usuario -> passphrase
2. Argon2id(passphrase + salt_verification) -> Se compara con master_key_hash
3. Argon2id(passphrase + salt_key_derivation) -> Clave AES-256
4. Encrypt/Decrypt con AES-256 + Nonce aleatorio

Campos cifrados:
- tables: name
- columns: name, data_type  
- mappings: origin_table, origin_column, destination_table, destination_column, transformation_logic
- entity_versions: snapshot, diff
- comments: content

## 3. VALIDACIONES (Migración 004)

Campos mutuamente excluyentes:
- Si is_encrypted=TRUE: nombre/tipo debe estar en _encrypted + _nonce (plaintext NULL)
- Si is_encrypted=FALSE: nombre/tipo debe estar en plaintext (_encrypted NULL)
- Nunca ambos NI ninguno

Ejemplo:
CHECK ((name IS NOT NULL AND is_encrypted = FALSE) OR 
       (name_encrypted IS NOT NULL AND name_nonce IS NOT NULL AND is_encrypted = TRUE))

## 7. IDs MIXTOS

## 8. NOTAS

- Soft delete: users.is_deleted, projects.is_deleted
- Cifrado es OPCIONAL pero si habilitado es OBLIGATORIO
- Timestamps mixtos (con/sin zona horaria)
- Enums: member_role (editor/viewer), table_type (origin/destination)
- ON DELETE CASCADE (excepto SET NULL en algunos casos)
